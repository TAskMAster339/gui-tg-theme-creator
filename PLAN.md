# План gui-tg-theme-creator

Цель — выбрать визуальный элемент Telegram Desktop, изменить его цвет и получить файл темы, пригодный для применения в клиенте.

- [ ] T008 Проверить пользовательский сценарий в KDE Plasma и Niri
  - Приёмка: в обеих Wayland-сессиях открывается исходная тема, редактируется цвет визуального элемента и экспортируется файл, который Telegram Desktop принимает.
  - Проверка: вручную пройти сценарий в обеих сессиях, применить экспорт и сравнить изменённый элемент с предпросмотром. Записать проверенную версию клиента.
  - Зависит от T007.
- [ ] T007 Добавить экспорт темы
  - Приёмка: редактор записывает `.tdesktop-theme` по выбранному пути и сохраняет обои и параметры, которых пользователь не менял.
  - Проверка: импортировать синтетический архив, изменить один цвет, экспортировать, проверить целостность архива и сравнить палитру и обои с исходником.
  - Зависит от T006.
- [ ] T006 Сделать выбор элемента и редактирование цвета
  - Приёмка: каждая строка показывает редактор свойств слева и живой пример компонента справа. Щелчок по части примера выделяет её свойство. Изменение цвета обновляет все связанные примеры. Есть поиск по компоненту и ключу.
  - Проверка: выбрать счётчик непрочитанных, подпись комментариев и кнопку профиля канала. Проверить ожидаемые ключи и обновление элементов с общим ключом.
  - Зависит от T005.
- [ ] T005 Сопоставить визуальные элементы с ключами палитры
  - Приёмка: каталог перечисляет ключи целевой версии, их назначение, компоненты, состояния и источники подтверждённых привязок. Начальные примеры охватывают счётчик непрочитанных, сообщение с ответом, пост канала с комментариями, действие меню, уведомление и кнопку профиля канала. Для ключей без примера или подтверждённой привязки виден их статус.
  - Проверка: сверить по исходникам клиента и на синтетической палитре как минимум обычный и заглушённый счётчики, подпись комментариев, разделитель настроек и фон кнопки профиля.
  - Зависит от T004 и T009.
- [ ] T004 Реализовать импорт и модель палитры
  - Приёмка: редактор создаёт тему из базовой палитры клиента, загружает текстовую палитру и архив темы, читает HEX и ссылки между ключами, сообщает о некорректных данных. Поля облачной темы и неизвестные поля доступны для проверки и сохраняются при обмене с форматом, который их поддерживает.
  - Проверка: на синтетических файлах проверить импорт архива с обоями, цвет с альфа-каналом, ссылку между ключами и ошибку при циклической ссылке.
  - Зависит от T003.
- [ ] T003 Создать каркас приложения
  - Приёмка: заданы зависимости, минимальное окно запускается, команды запуска и автоматических проверок описаны в репозитории.
  - Проверка: выполнить описанные команды в чистом окружении и открыть окно.
  - Зависит от T009.
- [x] T009 Инвентаризировать поля темы до реализации каркаса
  - Приёмка: отдельный реестр содержит все ключи палитры Telegram Desktop 7.4.1, поля облачной темы и варианты встроенных обоев. Проверка выявляет пропуски, неизвестные поля в привязках и дубли свойств. Отчёт показывает прогресс по каждому полю.
  - Проверка: выполнить `python3 scripts/check_catalog.py --upstream /путь/к/colors.palette` для закреплённой палитры и проверить отклонение повреждённых копий реестра. Порядок работы описан в [catalog/README.md](catalog/README.md).
  - Зависит от T002.
- [x] T002 Согласовать первую версию
  - Приёмка: определены режим визуального выбора, поддерживаемые форматы, версия Telegram Desktop, стек и границы компонентов.
  - Проверка: сверить зафиксированные решения в AGENTS.md с требованиями пользователя.
  - Зависит от T001.
  - Решение: отдельный редактор на Python и PySide6. Каждая строка представляет компонент Telegram. Слева свойства и инструменты, справа интерактивный пример. Готовая тема проверяется в Telegram Desktop.
  - Исследование: локально установлен Telegram Desktop 7.4.1 (Flatpak). Предлагаемая цель проверки — [исходники v7.4.1](https://github.com/telegramdesktop/tdesktop/tree/v7.4.1) и эта сборка клиента.
  - [Справочник темы](https://github.com/telegramdesktop/tdesktop/wiki/Theme-Reference) и [загрузчик](https://github.com/telegramdesktop/tdesktop/blob/v7.4.1/Telegram/SourceFiles/window/themes/window_theme.cpp) описывают текстовую палитру и ZIP с палитрой и необязательными обоями. При экспорте учитывать порядок ссылок на ранее заданные ключи. Сопоставление областей предпросмотра с ключами проверять по стилям и коду отрисовки целевой версии.
  - Проверку экспорта считать пройденной после применения файла в целевом клиенте и сравнения изменённых элементов. Публикацию проверять через [официальный сценарий облачных тем](https://core.telegram.org/themes). Для Android, iOS и нативного клиента macOS предусмотреть отдельные форматы и карты элементов в следующих версиях.
- [x] T001 Инициализировать репозиторий и рабочий процесс
  - Приёмка: в корне Git-репозиторий, AGENTS.md, PLAN.md и индекс проектных навыков.
  - Проверка: `git diff --cached --check` перед коммитом, затем `git status --short` без вывода и `git log -1 --oneline` с коммитом инициализации.
